# music-notation-rule-designer.md

> 담당 에이전트: `music-notation-rule-designer`  
> 관련 파일: `ml/data/tokenizer.json`, `ml/data/round_tokens/`, `ml/omr/utils/render_notation.py`

## 역할

DeepScore 커스텀 토큰 체계를 설계·관리하고, 일반 악보 기호와의 매핑 규칙을 정의한다.  
새 기호 추가 시 vocabulary 확장 방식을 결정하고, 커스텀 악보 표기법 시각 규칙을 유지한다.

### 토큰 형식

| 토큰 | 형식 | 예시 |
|---|---|---|
| 특수 | `<PAD>` `<SOS>` `<EOS>` `<UNK>` | — |
| 음자리표 | `clef-{G\|F\|C}` | `clef-G`, `clef-F` |

| 쉼표 | `rest-{dur}` | `rest-1/4` |
| 세로줄 | `barline`, `barline-double`, `barline-final`, `barline-start-repeat`, `barline-end-repeat` | — |

## 확장 토큰 규칙

### 셋잇단음표

래퍼 방식으로 기존 note 토큰 재사용:
```
tuplet-3-start
note-C4-1/8    ← 기반 음가 (실제 음가는 1/3 박)
note-E4-1/8
note-G4-1/8
tuplet-3-end
```

### 옥타브 기호

토큰 내 음높이는 **실제 연주 음높이** 기준 (악보 표기 그대로가 아님):
```
ottava-8va-start
note-C5-1/4   ← 악보에는 C4로 표기, 8va 범위 내 C5로 연주
ottava-8va-end
```

### 임시표 처리

새 토큰 불필요. 절대 pitch 토큰으로 표현:

| 기호 | 처리 |
|---|---|
| ♮ 네츄럴 | 절대 pitch 그대로 (`F♮` → `note-F4-1/4`) |
| 𝄪 겹올림 | 이명동음 (C𝄪 → `note-D`, D𝄪 → `note-E`, …) |
| 𝄫 겹내림 | 이명동음 (C𝄫 → `note-Bb`, D𝄫 → `note-C`, …) |

## 커스텀 악보 표기법 규칙

### 오선 구조

- 1번선(위)·5번선(아래) 두 줄만 표시하는 **직사각형 박스**
- 각 보표를 수직으로 **3등분** → 위·중·아래 존 = 각각 다른 옥타브
- 높은음자리(오른손) + 낮은음자리(왼손) 각 1개, 총 2단

```
높은음자리(오른손)
┌────────────────────┐  ← 위 존  (예: C5~B5)
├ ─ ─ ─ ─ ─ ─ ─ ─ ─┤  ← 중 존  (예: C4~B4)
├ ─ ─ ─ ─ ─ ─ ─ ─ ─┤  ← 아래 존 (예: C3~B3)
└────────────────────┘

낮은음자리(왼손)
┌────────────────────┐  ← 위 존  (예: C3~B3)
├ ─ ─ ─ ─ ─ ─ ─ ─ ─┤  ← 중 존  (예: C2~B2)
├ ─ ─ ─ ─ ─ ─ ─ ─ ─┤  ← 아래 존 (예: C1~B1)
└────────────────────┘
```

### 음 이름 표기

| 건반 | 표기 | 색상 |
|---|---|---|
| 흰 건반 (C D E F G A B) | 영문 대문자 | 흰색 글자 + 검은 외곽선 |
| 검은 건반 | 숫자 1~5 | 검은색 글자 |

검은 건반 숫자 매핑: 1=C#/Db, 2=D#/Eb, 3=F#/Gb, 4=G#/Ab, 5=A#/Bb

### 음가 표현

- 한 마디 = 박자수만큼 **균등한 셀**로 분할 (4/4박 → 4셀)
- 음표는 음가에 비례하는 셀 수 차지 (2분음표 → 2셀)
- 음표 글자는 차지한 셀들의 **정중앙**에 배치
- 빈 셀 = 쉼표 (별도 기호 없음)

### 셀 색상 테두리 (음표 순서 기준)

| 순서 | 테두리 색 |
|---|---|
| 1번 음표 | 주황 `#FF8C00` |
| 2번 음표 | 연두 `#7CFC00` |
| 3번 음표 | 하늘 `#00BFFF` |
| 4번+ | 위 순서 반복 |

마디선은 색상 순서를 리셋하지 않음.

### 기타 표기 규칙

| 항목 | 규칙 |
|---|---|
| 조표 | 표시 안 함 (변화음은 숫자로 표기) |
| 박자표 | 보표 왼쪽에 숫자 |
| 음자리표 | `T` (Treble) / `B` (Bass) 텍스트 레이블 |
| 셈여림 | 한국어 텍스트 (`세게`, `여리게`, `강조`, `짧게`) |
| 도돌이표 | `↩` 기호 또는 텍스트 `반복` |

### 마디 중간 클렙 전환 표기 (한 보표 내부)

표준 악보에서 **하나의 보표(치 또는 베이스) 안에서** 마디 중간에 음자리표가 바뀌었다가 복귀하는
경우(예: 치보표가 극저음 구간에서 잠시 낮은음자리로 전환)를 배경 색으로 구분한다.
대보표의 치/베이스 두 보표가 서로 다른 클렙을 쓰는 것(원래도 당연한 상태)과는 무관하며,
**같은 보표·같은 note 리스트 안에서 active clef가 실제로 섞여 있는 경우에만** 적용되는 규칙이다.

#### 데이터 모델

- note 단위로 active clef를 오버라이드하는 필드를 둔다. 값은 `'treble'` / `'bass'`.
- **기본값(미지정)은 보표 전체의 clef를 그대로 상속** — 즉 이 필드를 쓰지 않는 기존 note 리스트는
  동작·렌더링이 지금과 완전히 동일하다.
- Flutter: `ScoreNote.clef` (nullable, `lib/data/samples.dart`)
- 웹: note object의 optional `clef` 필드 (`online_webpage/js/samples.js`)
- 두 구현 모두 "note의 유효 클렙(effective clef) = note.clef ?? 보표 clef" 계산 함수와
  "리스트 안에 서로 다른 유효 클렙이 2개 이상 섞여 있는지" 판정 함수를 둔다
  (`effectiveClef()` / `hasMixedClef()`).

#### 배경 틴트 렌더링 규칙

| 활성 클렙 | 색상 | 불투명도 |
|---|---|---|
| 치(높은음자리, treble) | 청보라 `#6C63FF` | 10~15% |
| 베이스(낮은음자리, bass) | 호박색 `#FFB347` | 10~15% |

- **조건부 렌더링**: 같은 note 리스트 안에 실제로 서로 다른 active clef가 섞여 있을 때만
  (`hasMixedClef() == true`) 배경 틴트를 그린다. 섞여 있지 않으면 (기존 렌더링과 동일하게) 아무것도
  칠하지 않는다 — 기존 단일-클렙 화면의 색감을 절대 바꾸지 않기 위한 하드 조건.
- 섞여 있을 때는 **해당 보표의 모든 셀**을 각 note의 유효 클렙에 따라 칠한다 (오버라이드된 구간만이
  아니라 기본 클렙 구간도 칠해서, 지금 이 칸이 어느 클렙 기준으로 읽히는지 전체를 한눈에 비교할 수
  있게 한다).
- 틴트는 텍스트/테두리/하이라이트보다 **아래 레이어**에 그린다. 기존 하이라이트·expected(금색 점멸
  화살표) 상태 색상 로직은 그대로 유지하고, 그 위에 얹는 방식이다.
- 존(zone, 세로 위치) 계산도 note의 유효 클렙을 기준으로 한다 — 클렙이 바뀐 note는 바뀐 클렙 기준
  옥타브 존에 그려져야 시각적으로 "지금 낮은음자리로 읽는다"는 것이 옥타브 위치로도 드러난다.

#### 토큰 레벨

새 토큰은 필요 없다. 기존 vocab의 `clef-G` / `clef-F` 토큰이 마디 중간에 재등장하는 것으로 표현한다
(예: `clef-G note-... clef-F note-... clef-G note-...`).

**round3train 파이프라인 확인 결과(2026-07-30)**: `ml/omr/utils/render_notation.py`(Python 렌더러)는
상태 머신 방식이라 원래부터 재등장을 완전히 지원. 반면 학습 데이터 생성기
`round3train/generate_scores.py`는 기존에 보표당 clef 토큰을 정확히 1회만 방출하도록 막고 있어서
재등장 예시가 데이터에 전혀 없었음 — `CLEF_CHANGE_PROB`/`--clef-change-prob` 추가로 해결(단일 오선
생성 경로 한정, TrainingStep.md Step 2.5 참고). vocab 변경이 없으므로 tokenizer.json이나 기존
체크포인트에는 영향 없음.

#### 구현 상태

✅ 구현 완료 (2026-07-29) — `lib/data/samples.dart` / `lib/widgets/notation_widget.dart` /
`online_webpage/js/samples.js` / `online_webpage/js/notation.js`. 샘플 데이터에는 아직 클렙 전환
예시가 없음(기존 samples 배열은 의도적으로 건드리지 않음) — 필요 시 note에 `clef` 필드를 채운 새
샘플을 추가해서 시각 확인.
